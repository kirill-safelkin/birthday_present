# «Алиса и Чучмек» — правила разработки

Ретро-RPG на Python и Pygame. Разработка идёт поэтапно: задание каждого этапа даёт
пользователь. Отвечать и писать комментарии в коде на русском языке.

## Команды

Все команды выполняются из этой папки:

```bash
./.venv/bin/python main.py                                    # запуск игры
./.venv/bin/python -m compileall -q main.py config.py game tests   # проверка синтаксиса
./.venv/bin/python -m unittest discover -s tests -v           # все тесты
```

## Завершение этапа

1. После завершения каждого этапа сначала проверить код: синтаксис и все существующие тесты.
2. Если тесты не проходят, не коммитить незавершённый этап. Сообщить пользователю о проблемах.
3. Если тесты проходят и изменения проверены, самостоятельно создать локальный Git-коммит
   по правилам ниже.
4. Не переходить к следующему этапу, пока пользователь не получил отчёт о завершении текущего.

## Коммиты

- Игра — самостоятельный репозиторий (`origin` → `kirill-safelkin/birthday_present`,
  ветка `master`).
- Перед коммитом просмотреть `git status`, `git diff` и `git diff --cached` и проверить
  список файлов: в индексе должны быть только изменения текущего этапа. Если там есть
  посторонние подготовленные изменения, не включать их в коммит, а сообщить пользователю.
- Подготавливать файлы по явным путям: `git add -- <пути>`, а снимать с учёта
  с сохранением на диске — `git rm --cached -- <пути>`. Не выполнять бездумно
  `git add .`, `git add -A` и `git commit -a`.
- Когда весь подготовленный diff проверен, создавать обычный коммит `git commit -m "…"`.
  Не использовать механически `git commit -- <пути>`: он берёт указанные пути из
  рабочего дерева в обход индекса, и, например, файлы, снятые с учёта через
  `git rm --cached`, но оставшиеся на диске, вернутся в коммит.
- После коммита проверить `git show --stat HEAD` и `git status`: в коммите только
  задуманные файлы, рабочее дерево чистое.
- Не включать в коммиты виртуальное окружение, кэш, секреты, локальные настройки IDE
  (`.idea/`, `.vscode/`) и посторонние пользовательские файлы.
- Не использовать разрушительные Git-команды без отдельного разрешения пользователя:
  `reset --hard`, `clean`, `checkout -- .`/`restore` поверх чужих изменений, `rebase`,
  `commit --amend` уже существующих коммитов, `push --force`, удаление веток и `stash`.
- Сообщения коммитов писать в стиле Conventional Commits, например:
  `feat: add dialogue system`, `fix: correct dialogue transitions`,
  `test: cover scene progression`.
- Не создавать коммит после каждого мелкого вызова инструмента. Один завершённый
  этап — один основной коммит. Если после этого понадобилось исправление, допустим
  отдельный коммит `fix: …`.
- Не отправлять коммиты в удалённый репозиторий автоматически: только локальные
  коммиты, если пользователь отдельно не попросил выполнить `git push`.

## Особенности проекта

- Каждый модуль тестов сам задаёт `SDL_VIDEODRIVER=dummy` до импорта Pygame:
  `discover -s tests` не импортирует `tests/__init__.py`. Новые модули тестов делают
  так же, иначе тесты откроют настоящее окно.
- На машине разработки сломан OpenGL (драйвер NVIDIA), поэтому в `game/core/app.py` задана
  переменная `SDL_FRAMEBUFFER_ACCELERATION=0`. Не убирать её.
- Буквенные клавиши проверять и по `event.key`, и по `event.scancode`: у пользователя
  раскладки de и ru. Для этого есть `matches_key()` в `game/core/input.py`.
- Игровая логика использует логические действия (`Action`, `actions_for()`, `ActionInput`
  в `game/core/input.py`), а не конкретные клавиши. Экраны — сцены `game/core/scenes.py`;
  переходы только через `SceneManager` (`push`/`pop`/`replace`), а не прямыми вызовами.
- Повторный KEYDOWN без KEYUP игра считает автоповтором и пропускает. В тестах одно
  нажатие — это KEYDOWN и KEYUP (`press()` в `tests/test_app.py`).

## Структура проекта

- `game/core/` — игровой цикл, окно, ввод, сцены; `game/graphics/` — анимации, шрифты, спрайты;
  `game/dialogue/` — диалоги; `game/world/` — персонажи и (позже) карты;
  `game/story/` — сюжет: сценарии (только данные) отдельно от сцен, которые их показывают
  (в вступлении до сюжетного сбоя нельзя упоминать Чучмека, грибы и испытания);
  `game/debug/` — временные экраны проверки, не часть игры.
- Тесты лежат плоско в `tests/` и называются `test_<область>.py`.
- `assets/` — только то, что игра загружает во время работы (правила — в `assets/README.md`).
  `art/` — исходники и концепты, игра их не читает. Относительные пути к ресурсам
  считаются от `config.PROJECT_DIR`, а не от текущего каталога.
- Новую папку создавать вместе с первым файлом в ней: Git не хранит пустые папки.
- Спрайты персонажа описываются манифестом `assets/characters/<id>/<id>.json` (формат —
  в `assets/README.md`). Пиксели утверждённых кадров не менять; `tests/test_character_assets.py`
  проверяет все импортированные ресурсы.
